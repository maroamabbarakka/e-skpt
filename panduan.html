Panduan menggunakan e-PASAR

Pilih kebutuhan Anda. Setiap bagian menjelaskan apa yang perlu disiapkan, langkah yang dilakukan, dan hasil yang akan diterima.

01

Pendataan pedagang

  1. Siapkan NIK, nomor HP/WhatsApp, alamat, dan informasi usaha.
  2. Buka Form Pedagang, lalu isi lima langkah singkat.
  3. Jika menggunakan kios, los, atau lapak, tuliskan data tempat sebagai klaim awal.
  4. Jika mengajukan SKPT, siapkan foto penjual dan foto KTP. KTP hanya dapat dilihat petugas berwenang.
  5. Baca pernyataan, centang persetujuan, periksa kembali, lalu kirim.
  6. Simpan nomor registrasi untuk mengecek perkembangan atau meminta koreksi.
Aplikasi tidak menggunakan e-meterai. Persetujuan dicatat bersama versi pernyataan dan waktu pengiriman.
02

Admin Disperindag

  1. Masuk menggunakan akun jabatan.
  2. Buka antrean pendaftaran dan periksa identitas, usaha, lampiran, serta kemungkinan NIK ganda.
  3. Bentuk data induk hanya setelah pemeriksaan selesai.
  4. Data pedagang non-pasar selesai tercatat. Klaim pasar diteruskan kepada Kepala Pasar.
  5. Jangan mengubah NIK atau data induk dari permintaan informal; gunakan alur koreksi.
03

Kepala Pasar

  1. Buka Verifikasi Pasar dan pilih klaim pada pasar yang ditugaskan.
  2. Periksa nomor fisik, jenis unit, blok, lantai, luas, dan pengguna aktual.
  3. Tulis alasan pemeriksaan. Perubahan disimpan sebagai data sebelum dan sesudah.
  4. Jika unit sudah dipakai pedagang lain, sistem membuat konflik dan tidak menimpa pemegang lama.
  5. Untuk pelepasan atau pengalihan, gunakan halaman Perubahan Pemegang Unit. Pengajuan tidak langsung mengubah data.
04

Kadis

  1. Bandingkan data pemohon dan hasil pemeriksaan Kepala Pasar.
  2. Kembalikan atau tolak bila data belum sesuai; setujui bila pemeriksaan lengkap.
  3. Catat nomor dan referensi resmi sebelum menerbitkan SKPT.
  4. Untuk sementara TTE belum terintegrasi. Sistem hanya mencatat persetujuan Kadis, hash dokumen, serta referensi penerbitan.
  5. Putuskan permohonan pengalihan unit setelah dasar dan penerima baru diperiksa.
05

Status, dokumen, dan QR

  • Nomor registrasi digunakan untuk memantau proses pendataan.
  • QR SKPT digunakan untuk memeriksa dokumen.
  • QR unit melekat pada kios, los, atau lapak dan tidak berubah ketika pemegang berganti.
  • Halaman publik tidak menampilkan NIK lengkap, nomor HP, atau lampiran identitas.
  • Pengesahan tahunan tidak memperpanjang tanggal berakhir SKPT.
06

Keamanan data

  • Jangan membagikan password akun petugas.
  • Ganti password melalui halaman Profil & Keamanan.
  • Jangan mengirim NIK lengkap melalui WhatsApp atau email.
  • Gunakan tautan verifikasi dan ID pedagang untuk komunikasi layanan.
  • Laporkan data salah melalui permohonan koreksi, bukan dengan mengubah catatan secara diam-diam.
07

Catatan pengelolaan aplikasi

Aplikasi menggunakan Firebase paket Spark, tanpa Cloud Functions dan tanpa Firebase Storage. Foto diperkecil dan dikompres di perangkat sebelum disimpan. PDF tidak disimpan sebagai file besar di Firestore; yang dicatat adalah data dokumen, hash, status, dan referensinya.

Sebelum layanan dibuka untuk masyarakat, petugas harus menyelesaikan UAT, memeriksa Security Rules, mencatat kapasitas Firestore, dan memperoleh persetujuan pemilik proses.
